1. Token Storage and Security
We store the JSON Web Token in localStorage to allow the application to maintain the user's authentication state across page refreshes and browser sessions without forcing them to log in repeatedly. However, a major security risk of this approach is vulnerability to Cross-Site Scripting (XSS) attacks, as any malicious script injected into the application can easily read and exfiltrate the token. A more secure alternative is storing the JWT inside an HttpOnly, Secure cookie, which prevents client-side JavaScript from accessing it directly.

2. Purpose of AuthContext
The AuthContext provides a centralized global state management system for authentication, making user credentials and tokens seamlessly accessible across the entire component tree. Passing the token down as a prop through every single intermediary component leads to "prop drilling," which makes the codebase overly complex and difficult to maintain. Using context neatly solves this by allowing any component to consume authentication states and methods like login or logout directly from the provider.

3. Handling JWT Expiration
When a JWT expires, subsequent API requests made to the server will fail with an unauthorized status code, causing data fetches to break. To handle this gracefully, the ideal user experience involves intercepting these expiration errors, clearing out the invalid session state, and automatically redirecting the user back to the login screen with a notification message. Alternatively, implementing a silent token refresh mechanism in the background can renew the user's session without interrupting their workflow.

4. Backend Middleware vs. Frontend Protected Routes
The backend's requireAuth middleware operates at the server level to inspect incoming HTTP requests for a valid JWT, protecting database endpoints from unauthorized access or tampering. Conversely, the frontend's ProtectedRoute is a UI-level routing guard that controls whether a user can navigate to specific client views, redirecting unauthenticated users to the login screen for better usability. We need both because frontend route protection can easily be bypassed, making backend middleware the absolute source of truth and security for server resources.
